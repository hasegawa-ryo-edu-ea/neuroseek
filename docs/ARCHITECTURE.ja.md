# アーキテクチャ

英語版: [ARCHITECTURE.md](ARCHITECTURE.md)

不変の Wikidata トリプルは、コンパクトでメモリマップ可能な順方向・逆方向 CSR にコンパイルされます。ホットパスでは `uint64` のオフセット、`uint32` のノード ID、`uint16` の関係 ID を使い、文字列処理を避けます。人間向けのラベルは TSV の参照ファイルとして保持します。

Rust は NEURO-ISA の意味論、VM の計数、グラフ CPU リファレンス、証明検証を担当します。CUDA は SM87 向けにコンパイルした C ABI の一括処理を提供し、パリティテストでホスト参照と比較します。Python はクエリ条件付きナビゲータ、PPO 更新、カリキュラム／タスクアダプタ、チェックポイントのライフサイクル、追記型メトリクスを担当します。Rust の端末ダッシュボードは metrics JSONL を読み取るだけです。

ANN インターフェースは、コンテナ内のビルド・正確性テストに合格した場合に限り CAGRA を選択する設計です。初期状態で必須のバックエンドは CUDA の完全内積／top-k です。指定された smoke モード以外では、どちらの CUDA バックエンドも読み込めない場合に停止します。

本番イメージは NVIDIA L4T ML R36.2（JetPack 6 / CUDA 12.2 世代）に固定しています。検出された Jetson Linux R36.3 ホストが CUDA 12.2 を使うためです。最初に試した汎用 PyTorch 24.03 イメージは CUDA 12.4 のユーザー空間を含んでいました。PyTorch は Orin を列挙できましたが、カスタム CUDA PTX は未対応ツールチェーンエラーで失敗しました。そのため、コンテナから GPU が見えることを CUDA 互換性の証拠とは扱いません。`neuroseek-cuda-parity` を起動時の必須ゲートにしています。
