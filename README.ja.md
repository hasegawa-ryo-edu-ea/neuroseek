# NEUROSEEK（日本語）

**Jetson Orin Nano上で、大規模知識グラフを「根拠付き」で探索するためのGPUネイティブ研究システムです。**

NEUROSEEKは、単にもっともらしい候補を返す検索器ではありません。Wikidata5Mの大規模グラフを探索し、得られた答えがグラフ上の証拠によって成立しているかを独立に検証することを目指します。

英語版（詳細）: [README.md](README.md)

## どんなプロジェクトか

NEUROSEEKは次の要素を一つのJetson向け研究パイプラインに統合しています。

- **メモリマップCSRグラフ**: Wikidata5Mを文字列処理のないコンパクトな隣接配列として扱います。
- **Rust製NEURO-ISA VMと証明検証器**: 探索プログラムを実行し、答えのグラフ証拠を別系統で検証します。
- **CUDAプリミティブ**: 候補スコアリングなどの重い処理をOrinのGPUで実行します。
- **意味ベクトルレーン**: エンティティ埋め込みで候補ジャンプを提案します。ただし、意味検索だけで真実とみなすことはありません。
- **学習済みナビゲータ方策**: クエリに応じ、限られた探索予算の中でどの操作を使うかを学習します。

目的は「答えを当てる」ことだけではなく、**なぜその答えが正しいのかを後から検証できる探索**を、エッジGPU上で成立させることです。

## 優れている点

| 特長 | 意味 |
| --- | --- |
| 証明を必ず検証 | 答えの報酬は、Rustの独立した検証器がグラフ証拠を受理した場合にのみ与えられます。 |
| CUDAを安易に信用しない | GPUが見えているだけでは起動を許可せず、カスタムCUDA実装とCPU参照実装のパリティ検証を通します。 |
| 完全な意味ベクトルを検証 | `semantic_full` はハッシュ、次元、エンティティID順序、全ID被覆を確認し、部分モデルをフル実験に混ぜません。 |
| 長時間実行に耐える | 原子的チェックポイント、再開検証、空き容量保護、温度異常時の保存して停止、という安全策を備えます。 |
| SSHを切っても動く | 学習器は端末から分離して起動します。再接続時のTUI表示は読み取り専用で、二重学習を起こしません。 |

## レイテンシについて（重要）

現時点のNEUROSEEKは、低レイテンシを達成済みの製品ではありません。正確性を優先したCUDA完全スコアリングとホスト側top-k統合、さらに方策とVMの往復が、レイテンシ上の主な制約です。この点は隠さず、最適化対象として扱っています。

### 現在進行中の改善

このREADME更新時点では、約6時間を目安とするレイテンシ特化モデルの学習を実行中です。観測済みのCUDA探索コストから作成したコストモデルを使い、次を同時に最適化します。

- 予測クエリレイテンシへの小さなペナルティ
- NEURO-ISA命令数への小さなペナルティ
- 証明の正当性を壊さないための、十分に大きい有効証明の報酬

これは「速く見せる」ための変更ではありません。固定された未使用評価タスクで、答えの正確性と証明有効性を維持できるかを確認して初めて改善として扱います。現時点では、改善率やミリ秒値はまだ記載しません。

## 起動方法

### 1. 必要環境

検証対象はJetson Orin Nano、Jetson Linux R36.3 / JetPack 6世代、NVIDIA Container Runtime、Docker Composeです。フル実行の前にはおおむね24 GiB以上の空きディスクを確保してください。

データとモデルは100 MBを超えるため、Git本体ではなくGitHub Releaseに置かれています。

```bash
git clone https://github.com/hasegawa-ryo-edu-ea/neuroseek.git
cd neuroseek

# 非公開リポジトリなので、事前に gh auth login が必要です。
gh release download initial-data-and-models \
  --repo hasegawa-ryo-edu-ea/neuroseek \
  --pattern 'neuroseek-*.tar.zst'

sha256sum -c data/RELEASE_SHA256SUMS
tar --zstd -xf neuroseek-wikidata5m-raw.tar.zst
tar --zstd -xf neuroseek-processed-data-and-models.tar.zst
```

これにより `data/raw/wikidata5m/` と `data/processed/` が復元され、完全な`semantic_full`モデルも利用できるようになります。

### 2. まず動作環境を確認

```bash
./up.sh --doctor
```

GPUが見えているだけでは十分ではありません。doctorはDocker/NVIDIA実行環境と公開面を確認します。

### 3. 実行モードを選ぶ

| コマンド | 用途 |
| --- | --- |
| `./up.sh --smoke` | 合成データによる短時間の機能・CUDAパス確認。科学的な評価結果ではありません。 |
| `./up.sh --trial` | 実データの決定的な部分グラフトライアル。部分semanticモデルを明示的に許可します。 |
| `./up.sh` | 完全semanticモデルを使う、本番相当の分離学習／再開。 |
| `./up.sh --status` | 分離された学習器の状態確認。 |
| `./logs.sh` | 現在runのログ確認。 |
| `./down.sh` | データとチェックポイントを残したまま安全に停止。 |

最初のフル実行では、学習器を分離する前にsemantic準備が前景で走る場合があります。`NEUROSEEK trainer detached:` またはTUIが表示されるまではSSHを切らないでください。中断しても、再度 `./up.sh` を実行すれば原子的チェックポイントから再開します。

### 4. SSH再接続後の表示

学習器が分離済みなら、SSHを切っても処理は継続します。再接続後に次を実行します。

```bash
cd /path/to/neuroseek
./up.sh
```

既存の学習器が健全なら、新しい学習を始めず読み取り専用TUIを表示します。TUIなしで状態確認する場合は `./up.sh --no-tui` を使います。

### 発表用Showcase TUI

発表向けの高コントラスト表示は、読み取り専用Rust TUIをビルドして現在のrunへ接続します。

```bash
./watch ja
```

英語版は`./watch`で起動できます。ヘルパーは必要な場合だけビルドし、現在のrunへ接続してシネマティックな全画面表示を開きます。最新の永続検索プログラムから「あみだくじ」風の探索ラティスを描画し、探索・証明、方策、Jetsonテレメトリを表示します。読むのは`metrics.jsonl`だけです。`Ctrl-C`は表示を閉じるだけで、学習器の停止・再開・制御は一切行いません。

`1` は探索、`2` は経路、`3` はシステム、`4` はモデルの表示へ切り替えます。`l`で表示言語を切り替えます。`/`でCodex風のローカルコマンドバーを開き、`/help`、`/lang ja`、`/lang en`、`/quit`を利用できます。1フレームだけ表示してスクリーンショットを撮る場合は`--once`、色なしのログ出力には`--no-color`を付けます。

分離済みの学習器が健全なら、`./up.sh`はこの監視TUIを自動で開くようになりました。起動処理だけを確認したい場合は`./up.sh --no-tui`を使います。

### 実モデル検索コンソール

動画・デモで実際の検索を見せるときは、学習済み方策の検索コンソールを起動します。

```bash
./search ja
```

英語版は`./search`です。これは独立したCPU専用・読み取り専用プロセスであり、固定済みの発表用チェックポイントとメモリマップグラフだけを読み込みます。CUDAコンテキストを作らず、`metrics.jsonl`への書込みや学習器へのシグナル送信もしません。そのため、別の学習ジョブがGPUを使っている間も安全に実行できます。

`r`でロード済みモデルを不変の検証タスクに対して実行し、`n`で次のタスク、`1`〜`5`で単語検索／モデル／経路／証明／システムを切り替え、`l`で言語を切り替えます。`:`から`:run 3`、`:lang ja`、`:quit`などを入力できます。演算子ラティス、候補、回答、証明状態はその実方策の実行結果です。正解参照値はモデル入力から分離されています。

最初の**単語検索**ページは、用意済みタスクではなく自分の語で調べるための画面です。`:`を押して`:find 日本`（英語なら`:find Japan`）と入力してください。語をWikidataのQ-ID候補へ解決し、ローカルグラフにある候補を強調して、実際の出力エッジを展開します。`:use 2`で別の候補を選び、`:rel 首都`（英語なら`:rel capital`）で関係をP-IDへ解決して表示中のローカルエッジを絞り込めます。名称解決には公開Wikidata APIを使いますが、グラフ探索・対象・証拠はすべてローカルの読み取り専用データです。ネットワークがない場合もQ/P IDを直接入力できます。

## 結果を読むときの注意

`runs/` にはメトリクスとマニフェストが保存されます。初期の`cuda_search_microbenchmarks`フェーズでは、方策報酬や証明指標がゼロまたは`n/a`でも正常です。コストモデルとBehavior Cloningフェーズの後から、方策の品質指標が意味を持ちはじめます。

フルな研究結果として報告する際は、最低でも設定・データ・semanticのハッシュ、未使用評価に対する正確性と証明有効性、探索量／命令数／ANN呼び出し／レイテンシ、電力・温度状態を併記してください。

コンテナ起動成功、スモークテスト、部分semanticモデルは、Wikidata5M全体での性能証明にはなりません。

## 構成

```text
config/     実験設定、実行時間、熱・ストレージ安全策
cuda/       SM87向けCUDA実装とCPUとのパリティテスト
data/       Releaseデータ／モデルの復元手順とチェックサム
docs/       設計、データ形式、意味レーン、運用手順
python/     学習、方策、データ、評価、テレメトリ
rust/       VM、証明検証器、CLI、読み取り専用TUI
scripts/    前処理、semantic構築、検証、事前確認
tests/      Pythonの正しさ・再開テスト
```
